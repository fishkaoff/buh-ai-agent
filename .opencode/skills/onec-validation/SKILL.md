# onec-validation — валидация данных 1С

## Когда использовать

- Перед созданием любого объекта/документа — до POST, а не после.
- Перед проведением документа.
- При сомнениях в данных пользователя (частичный ИНН, нет договора, несколько организаций).

Валидация — это запросы чтения, они безопасны.

## Чек-лист перед созданием объекта/документа

1. **Существование ссылок**: каждый `_Key` получен из ответа 1С **в этой же базе** в рамках текущей работы (не из памяти, не из другой базы). Проверка: GET `Catalog_Имя(guid'...')?$select=Ref_Key` → 200. Ref_Key из другой базы даёт пустой результат, а не ошибку.
2. **Не папка и не помечен**: `IsFolder=false`, `DeletionMark=false` у всех ссылок на элементы.
3. **Антидубликат**: перед созданием контрагента/номенклатуры/договора — поиск по наименованию и ИНН (Skills `onec-counterparties`, `onec-nomenclature`, `onec-contracts`). Найдено → использовать, не создавать. Повторный вызов операции — тоже сначала повторный поиск.
4. **Владелец подчинённого**: договор принадлежит контрагенту документа (`Owner_Key`); банковский счёт — организации. Нарушение → ошибки проведения.
5. **Вид договора** соответствует операции (`СПокупателем` для продаж; список — `docs/onec-metadata-map.md`).
6. **Валюта документа** = валюте взаиморасчётов договора (рубли — `Code 643`).

## Чек-лист табличной части

- `Количество > 0`, `Цена >= 0` в каждой строке; `LineNumber` — 1..N без пропусков.
- `Сумма` строки = Количество × Цена (до копеек); `СуммаДокумента` = Σ строк.
- Для услуг заполнено `Содержание` (текст печатной формы).
- **Ставка НДС** каждой строки — допустимое значение перечисления конфигурации (см. ниже); `СуммаНДС` рассчитан и согласован.

## Проверка ставки НДС (проверено на этой конфигурации)

1. Пользователь явно назвал ставку → использовать её. Не подменять значением по умолчанию.
2. Иначе — ставка по умолчанию из `config/onec-config.json` (`defaults.vatRate`).
3. **Допустимость проверять по `$metadata`** (`EnumType` `СтавкиНДС`, Skill `onec-metadata`, скрипт `scripts/metadata_extract.js`). Факт: в этой конфигурации допустимы `БезНДС, НДС0, НДС10, НДС10_110, НДС18, НДС18_118, НДС20, НДС20_120`; **ставок НДС5/НДС7/НДС22 нет** — запись отклоняется ошибкой 400 `Перечисление 'СтавкиНДС' не содержит элемент 'НДС5'`. Не полагайтесь на списки ставок из других версий 1С или из схем внешних инструментов.
4. Если нужной ставки нет в конфигурации — сообщите пользователю и спросите, чем заменить (например `НДС20` или `БезНДС`). Молча не подменяйте.
5. «Без НДС» в документе: флаг `ДокументБезНДС: true` в шапке + `СтавкаНДС: "БезНДС"` + `СуммаНДС: 0` в строках.
6. Уровни ставки в конфигурации: строка документа (основной), номенклатура (`Catalog_Номенклатура.ВидСтавкиНДС` — вид ставки: `Общая`, `Пониженная`, …), шапка (`ДокументБезНДС`). Определяющая для печати и проводок — ставка строки.
7. Расчёт суммы НДС: при `СуммаВключаетНДС=true` → `Сумма × ставка/(100+ставка)`, иначе `Сумма × ставка/100`; до копеек. Пример: 100000 × 20/120 = 16666,67.

## Проверка готовности к проведению

1. Шапка: организация, контрагент, договор, валюта — все `_Key` заполнены и существуют.
2. **Счета учёта (`*_Key` полей-счетов) брать только из плана счетов по коду** (`ChartOfAccounts_Хозрасчетный?$filter=Code eq '62.01'`): OData не валидирует GUID счетов при записи — неверный GUID сохранится и проявится при проведении.
3. `Posted=false` (документ ещё не проведён).
4. Табличная часть непуста и прошла чек-листы выше; `СуммаНДС` строк заполнен (для НДС-документов).
5. Реализация товаров: склад заполнен, остатки есть (запрос остатков — регистр накопления/аналитика; без остатков 1С проведёт с красным сальдо).
6. Согласованность: ставки НДС строк ↔ флаги шапки; суммы строк ↔ `СуммаДокумента`.

## Проверка после записи

1. Перечитать шапку — сверить все записанные поля.
2. Перечитать строки — сверить количества/цены/суммы/ставки/НДС.
3. Только после этого считать операцию успешной; расхождение — Skill `onec-error-handling`.

## Идемпотентность

- Прямой OData идемпотентности не имеет: перед повторным POST — антидубликат-поиск (наименование/номер/сумма/дата/контрагент).
- Показ пользователю payload до записи + чтение ответа 201 (там `Ref_Key`) — основа безопасного повторяемого процесса.
