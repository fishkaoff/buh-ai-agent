# Служебные справочники конфигурации (проверено 10.11.2026 на базе ai_agent)

Всегда перечитывайте GUID запросом — данные базы меняются. Здесь — проверенные значения и правила выбора.

## Валюты — `Catalog_Валюты`

- Рубль: `Code = "643"`, Ref_Key `ea9005c5-7320-11ec-95fd-0242ac120003` (поле `Description`: «руб.»).
- Выбор валюты для документа: `$filter=Code eq '643'`. Код валюты по умолчанию — в `config/onec-config.json` (`defaults.currencyCode`).

## Единицы измерения — `Catalog_КлассификаторЕдиницИзмерения`

Элементы (Description): `шт`, `кг`, `л`, `1000 руб`. Ref_Key «шт»: `34394c2c-7321-11ec-8111-0242ac120003`.

- Номенклатура ссылается полем `ЕдиницаИзмерения_Key`.
- В строках счёта покупателю единица не хранится (только количество), в строках реализации — `ЕдиницаИзмерения_Key`.
- Нужной единицы нет → попросите пользователя добавить её в 1С; через OData/MCP создавать не следует.

## Склады — `Catalog_Склады`

В базе один склад: «Основной склад», Ref_Key `34394c2a-7321-11ec-8111-0242ac120003` (не папка). В счёте покупателю поле `Склад_Key` — необязательное; в реализации товаров используется.

## Банковские счета организаций — `Catalog_БанковскиеСчета`

- Владелец — организация (полиморфное поле `Owner` + `Owner_Type`, НЕ `Организация_Key`).
- Ключевые поля: `НомерСчета`, `Банк_Key` (→ `Catalog_Банки`), `Description` (представление).
- В базе ai_agent один счёт: Ref_Key `a44d1e7b-dc3a-11f1-9a8f-a02942832943`, № `40802810900000012345` (Code `00-000011`).
- В счёте покупателю банковский счёт организации хранится в поле `СтруктурнаяЕдиница_Key` — так 1С печатает «реквизиты для оплаты». MCP-инструмент `write_sales_create_invoice` заполняет его сам (основной счёт организации или параметр `orgBankAccount`). При прямом POST — подставляйте Ref_Key счёта из `Catalog_БанковскиеСчета`.

## Банки — `Catalog_Банки`

Классификатор банков (БИК, наименование). Используется при создании банковских счётов; самостоятельно заполнять не требуется.

## Контактная информация контрагентов

Табличная коллекция `КонтактнаяИнформация` в `Catalog_Контрагенты` (виды: адрес, телефон, email). MCP `write_counterparty_create_counterparty` принимает `phone`/`email`/`address` и заполняет её сам. Прямое редактирование контактной информации через OData сложнее (составной RowType) — предпочитайте MCP.
