# onec-reference-data — справочники 1С

## Когда использовать

- Найти элемент справочника и получить его `Ref_Key`.
- Проверить существование объекта перед созданием (антидубликат).
- Создать или изменить элемент справочника.
- Работать со служебными справочниками: валюты, единицы, виды номенклатуры, склады, банки.

Транспорт — Skill `onec-odata` (клиент `config/onec/odata-client.js`). Имена объектов и реквизитов — Skill `onec-metadata` и `docs/onec-metadata-map.md`.

## Поиск и проверка существования

Правило: **сначала искать, потом создавать**. Выборку фильтруйте локально — надёжнее OData-фильтра по кириллице:

```js
const items = rows((await c.req("GET", c.BASE + "Catalog_Номенклатура?$format=json&$top=1000")).body);
const found = items.filter(x => !x.IsFolder && !x.DeletionMark
  && x.Description && x.Description.toLowerCase().includes(q.toLowerCase()));
```

Для точечных проверок эффективнее серверный фильтр: `$filter=ИНН eq '...'` или `$filter=substringof('текст', Description)` (Skill `onec-odata`).

- Всегда исключайте папки (`IsFolder`) и помеченные на удаление (`DeletionMark`).
- Совпадение считается дублирующим при равенстве наименований (без регистра) или совпадении ИНН(+КПП). Несколько совпадений — показывайте пользователю все варианты; выбор за человеком.
- Элемент найден — используйте его `Ref_Key`; не создавайте копию.

## Ссылки на объекты

- Ссылка элемента — `Ref_Key` (GUID). В документах: собственные поля — `Поле_Key`; составные типы — пара `Поле` + `Поле_Type`.
- Подчинённые справочники (договоры, банковские счета, контактные лица) определяются владельцем: `Owner_Key` = `Ref_Key` владельца.
- Ref_Key действуют только в своей базе — чужая ссылка даёт пустой результат, а не ошибку.

## Создание (прямым OData)

POST `Catalog_Имя?$format=json` с телом из обязательных полей. Успех — **201**, в ответе объект с присвоенными `Ref_Key` и `Code` (1С нумерует коды сама). Проверенный минимальный состав:

| Справочник | Минимальное тело POST |
|---|---|
| Контрагент | `{ "Description": "...", "ИНН": "...", "ЮридическоеФизическоеЛицо": "ЮридическоеЛицо"|"ФизическоеЛицо" }` |
| Договор | `{ "Description": "N от ДД.ММ.ГГГГ", "Номер": "N", "Дата": "…T00:00:00", "Owner_Key": "<контрагент>", "Организация_Key": "...", "ВидДоговора": "СПокупателем", "ВалютаВзаиморасчетов_Key": "<руб. 643>" }` |
| Номенклатура | `{ "Description": "...", "Услуга": false|true }` — 1С сама дозаполнит вид, единицу («шт»), номенклатурную группу и вид ставки НДС (проверено); при необходимости дозаполнить PATCH-ом |
| Банковский счёт | `{ "Description", "НомерСчета", "Банк_Key", Owner+Owner_Type }` |

Правила:

- Записывайте только данные, названные пользователем (никаких «додуманных» адресов/телефонов).
- После создания перечитайте объект — сверьте `Code`/автозаполнение и свои поля.

## Изменение

- PATCH `Catalog_Имя(guid'...')?$format=json` — только явно указанные пользователем поля; после записи перечитайте и сверьте.
- Перемещение в группу — PATCH `Parent_Key`. Папки создаются POST-ом с `IsFolder: true`.
- Мягкая пометка на удаление — PATCH `DeletionMark: true` (только по явному разрешению; физических удалений нет).

## Служебные справочники (база ai_agent, проверено 10.11.2026)

Полные данные — `references/catalogs.md` и `docs/onec-metadata-map.md`; GUID перечитывайте запросом.

| Справочник | EntitySet | Ключевое поле выбора |
|---|---|---|
| Валюты | `Catalog_Валюты` | `Code eq '643'` — руб. |
| Единицы измерения | `Catalog_КлассификаторЕдиницИзмерения` | `Description` («шт», «кг», «л», «1000 руб») |
| Виды номенклатуры | `Catalog_ВидыНоменклатуры` | `Description` («Товары», «Услуги», …) |
| Склады | `Catalog_Склады` | `Description` |
| Банковские счета организаций | `Catalog_БанковскиеСчета` | `НомерСчета`; владелец — организация (`Owner`+`Owner_Type`) |
| Банки | `Catalog_Банки` | классификатор БИК |

## Ограничения

- Служебные значения (валюты, единицы, виды номенклатуры) не создавайте — выбирайте из существующих; отсутствующие единицы просит добавить пользователь.
- Существующие элементы не изменяйте без явного разрешения (на них ссылаются документы).
- Если в среде доступен MCP `1c-odata` (инструменты `write_counterparty_*`, `write_catalog_*`), он даёт тот же результат с предпросмотром — см. `docs/onec-capabilities.md`; Skill самодостаточен и без него.
