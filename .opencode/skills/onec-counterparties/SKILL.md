# onec-counterparties — контрагенты 1С

## Когда использовать

- «Найди контрагента…», «есть ли у нас X», «выстави счёт Y» (первый шаг).
- Заведение нового контрагента по реквизитам.
- Изменение реквизитов, перенос в группу, банковские счета, контактные лица.

Транспорт — Skill `onec-odata`; метаданные `Catalog_Контрагенты` — Skill `onec-metadata`, карта — `docs/onec-metadata-map.md`.

## Поиск

```js
// по точному ИНН (серверный фильтр, эффективный):
GET Catalog_Контрагенты?$format=json&$filter=ИНН eq '<ИНН>'
// по подстроке названия:
GET Catalog_Контрагенты?$format=json&$filter=substringof('<текст>', Description)
// резервный путь — локальный фильтр по Description (Skill onec-odata)
```

- Поиск 1С без учёта регистра.
- Исключайте папки (`IsFolder`) и помеченные (`DeletionMark`).
- Найдено несколько — показать пользователю все варианты (наименование + ИНН + КПП), выбор за человеком. Не выбирайте «первый» сами.

## Проверка на дубль перед созданием

1. Поиск по ИНН → есть элемент: сравнить наименование. Даже при другом написании — предложить существующий.
2. ИНН не найден, но наименование совпало (без регистра) → вероятный дубль, уточните у пользователя.
3. Ничего не найдено → создание разрешено после показа предпросмотра payload.

## Карточка контрагента

GET `Catalog_Контрагенты(guid'...')?$format=json`. Ключевые реквизиты (проверено): `Description` (краткое), `НаименованиеПолное`, `ИНН`, `КПП`, `ЮридическоеФизическоеЛицо` (`ЮридическоеЛицо`/`ФизическоеЛицо`), `ОсновнойБанковскийСчет_Key`, `ОсновноеКонтактноеЛицо_Key`, `Самозанятый`, `ИндивидуальныйПредприниматель`, `Комментарий`. Полный состав — в карте метаданных.

## Создание

POST `Catalog_Контрагенты?$format=json` — проверенный минимум:

```json
{ "Description": "ООО Ромашка", "ИНН": "7701234567", "КПП": "770101001", "НаименованиеПолное": "ООО «Ромашка»", "ЮридическоеФизическоеЛицо": "ЮридическоеЛицо" }
```

Ответ 201 → `Ref_Key` и присвоенный 1С `Code`. Порядок: предпросмотр payload → согласие пользователя → POST → перечитать и сверить ИНН/наименование.

- `ЮридическоеФизическоеЛицо`: организации — `ЮридическоеЛицо`; ИП и самозанятые — `ФизическоеЛицо` (КПП у ИП нет).
- Контактную информацию (телефон/email/адрес) заполняйте только если пользователь назвал: коллекция `КонтактнаяИнформация` — RowType-записи (вид, значение); сложнее, чем шапка, — при наличии точного требования проверяйте структуру в `$metadata`.
- ОГРН и прочие «настраиваемые» реквизиты в типовой БП — дополнительные реквизиты; без настроенного доп.реквизита поле не пишется.

## Изменение

- PATCH `Catalog_Контрагенты(guid'...')?$format=json` — только явно указанные пользователем поля (например `{ "ИНН": "...", "Description": "..." }`), затем перечитать.
- Перенос в группу: PATCH `Parent_Key` (GUID группы или пустой GUID — корень).

## Связанные объекты

- Договоры — `Catalog_ДоговорыКонтрагентов` (владелец `Owner_Key`): Skill `onec-contracts`.
- Банковские счёта — `Catalog_БанковскиеСчета` (`Owner`+`Owner_Type`); создание — POST (БИК-справочник `Catalog_Банки`).
- Контактные лица — `Catalog_КонтактныеЛица` (владелец — контрагент).
- История продаж/закупок и взаиморасчёты — документы и регистры (счёт 62/60): поиск документов фильтром `Контрагент_Key eq guid'...'`; сверка — ОСВ по счёту с субконто-контрагентом.

## Ограничения

- Внешние источники данных (ЕГРЮЛ, карты партнёров) не интегрированы — работайте только с данными пользователя и 1С.
- Удаление недоступно (только мягкая пометка `DeletionMark`; не использовать без явного разрешения).
- В документах ссылаться только на элементы (не на папки).
