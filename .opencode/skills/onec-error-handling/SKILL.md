# onec-error-handling — ошибки 1С и OData

## Когда использовать

- Любой нестандартный ответ HTTP от 1С.
- Документ не провёлся или провёлся не так.
- Потерялся ответ при записи; неясно, создался ли объект.

## Формат ошибки OData 1С

```json
{ "odata.error": { "code": "6", "message": { "lang": "ru", "value": "Сегмент пути Name не найден!" } } }
```

Разбор — `parseError(status, body)` из `config/onec/odata-client.js`. Каталог проверенных ошибок — `references/errors.md`.

## Алгоритм реакции

1. **Прочитать код HTTP и `odata.error.code`**:
   - 400 «Сегмент пути … не найден» — несуществующее поле/EntitySet → сверить с `$metadata` (Skill `onec-metadata`); не ретраить.
   - 400 с упоминанием перечисления («Перечисление 'X' не содержит элемент 'Y'») — недопустимое значение (реальный пример: запись `НДС5` в конфигурацию без этой ставки) → взять допустимые значения из `$metadata`, согласовать с пользователем.
   - 401 — неверные креды; 404 (HTML) — неверный URL/порт; 501 — неподдержанная опция (`$expand`). Не ретраить.
   - 500 — ошибка записи 1С (нарушение бизнес-логики, обязательных полей). Сообщение бывает расплывчатым («Не удалось записать: …») — см. «Неизвестный исход записи» ниже.
2. **Соединение закрыто / таймаут** — 1С обрабатывает запросы одной учётки по очереди; один повтор этого же запроса. «Пустой результат» после ошибки соединения ≠ «данных нет».
3. **Неизвестный исход записи** (таймаут/500 после POST):
   - НЕ повторяйте POST сразу — двойное создание.
   - Сверьтесь с базой: GET по ожидаемым признакам (для справочника — наименование/ИНН; для документа — поиск по контрагенту/сумме/дате через EntitySet с фильтром) либо поиск по точному предпросмотренному payload.
   - Объект есть → использовать его, не создавать копию.
   - Объекта нет → подождите ≥ 120 с (1С могла ещё обрабатывать запрос) и повторите сверку; затем — один повторный POST по антидубликат-правилу (Skill `onec-validation`). В среде с MCP `1c-odata` ту же работу делает `write_operation_status` (см. `docs/onec-capabilities.md`).
4. **Ошибка проведения** — см. ниже.

## Ошибки проведения

- PATCH `Posted:true` вернул 200/204, но документ остался `Posted=false` — 1С отклонила проведение. Перечитайте документ; причины (проверенный порядок): незаполненные обязательные реквизиты (договор, склад для товаров), отрицательные остатки товаров, не заполненные `СуммаНДС`/счета учёта в строках.
- Проведён, но проводок нет/неполные — сверить `СуммаНДС` строк и счета доходов/расходов; проводки читать из регистра бухгалтерии `AccountingRegister_Хозрасчетный` (фильтр по реквизиту регистратора) или аналитикой (Skill `onec-sales-realizations` — ожидаемые схемы).
- Красное сальдо после проведения — неверные суммы/счета/остатки; до выяснения не проводите следующие документы.

## Когда эскалировать пользователю

- Ошибка повторяется после одного корректного ретрая и диагностики.
- Неоднозначность выбора (несколько похожих контрагентов/договоров/номенклатуры).
- Операции вне возможностей OData: изменение проведённого документа, физическое удаление, закрытие месяца, ручные проводки, печатные формы/PDF.
- Расхождение данных после записи (`СуммаДокумента` ≠ Σ строк и т.п.).
- Сообщение об ошибке не даёт причины (грубый 500) — человек должен посмотреть журнал регистрации 1С.

Никогда не «чините» данные молча повторными записями.

## Запрещено

- Ретраить 400/401/404 (не временные ошибки).
- Менять `config/onec-config.json` (креды/URL) без явного указания пользователя.
- Удалять/помечать объекты, чтобы «убрать ошибку».
