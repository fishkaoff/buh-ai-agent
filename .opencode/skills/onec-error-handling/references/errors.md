# Каталог ошибок 1С OData (проверено на практике)

## HTTP-коды

| Код | Ситуация | Действие |
|---|---|---|
| 200/204 | Успех чтения/изменения | — |
| 201 | Успешный POST (в теле — созданный объект с Ref_Key) | перечитать ключевые поля |
| 400 | Неверный запрос: несуществующее поле, недопустимое значение перечисления, неподдержанная функция фильтра | сверить с `$metadata`; не ретраить |
| 401 | Неверная авторизация Basic | проверить креды; не ретраить |
| 404 (HTML) | Неверный URL/порт веб-сервера (не 1С-ошибка) | проверить ODATA_BASE_URL |
| 404 (JSON) | Key-lookup несуществующего/невозможного EntitySet (напр. `_Товары(guid'...')`) | читать табличную часть фильтром по Ref_Key |
| 500 | Ошибка записи 1С (бизнес-логика/обязательные поля) — сообщение бывает расплывчатым | сверить объект в базе; см. «Неизвестный исход записи» в SKILL.md |
| 501 | Неподдержанная опция (`$expand=Товары`) | убрать опцию |

## Проверенные сообщения odata.error

| code | value | Причина | Решение |
|---|---|---|---|
| 6 | `Сегмент пути Name не найден!` | фильтр/путь по несуществующему полю (`Name` вместо `Description`) | смотреть поля через `$metadata` |
| 8 | `Сущность 'X' не найдена` | неверное имя EntitySet | найти через `$metadata`/`find` |
| -1 | `Не удалось записать: "Счет-фактура выданный"!` | 500 при записи СФ; причина в журнале регистрации 1С | сверить базу; упростить payload; см. SKILL.md |
| — | `Перечисление 'СтавкиНДС' не содержит элемент 'НДС5'` (при записи) | ставка НДС отсутствует в конфигурации (допустимы: БезНДС, НДС0, НДС10, НДС10_110, НДС18, НДС18_118, НДС20, НДС20_120) | выбрать допустимую ставку, согласовать с пользователем |
| — | `Значение "..." не является допустимым` (при записи) | значение перечисления/ссылки не из конфигурации | проверить EnumType в `$metadata` / Ref_Key этой базы |

## Ошибки соединения

- `ECONNREFUSED` — неверный хост/порт (например, попытка идти на MCP-прокси вместо сервера 1С). Проверьте `ODATA_BASE_URL`.
- `Connection closed` / таймаут — 1С обрабатывает запросы учётки по очереди; тяжёлый запрос мог не уложиться. Один повтор. Не делайте параллельных запросов.
- Пустой ответ после ошибки соединения ≠ отсутствие данных — повторите чтение.

## Ошибки проведения (типовые причины)

| Проявление | Причина | Решение |
|---|---|---|
| POST 201, PATCH Posted:true → 200, но Posted=false | 1С отклонила проведение (см. тело PATCH-ответа) | прочитать сообщение; проверить обязательные поля |
| Проведён, проводок нет / не все | пустая табличная часть, не заполнены счета учёта | проверить `read_accounting_get_document_postings` |
| Красное сальдо 41/10 | списание товара без остатка | проверить остатки `read_analytics_get_inventory` |
| Расчёты не встали на 62/60 | не заполнен договор или счёт расчётов по договору | заполнить договор; настройка — по договору |

## Порядок эскалации

1. Один повтор для сетевых ошибок.
2. Диагноз: HTTP-код + odata.error.code + сообщение + какая операция.
3. Пользователю: что делали, что получили, какие варианты (включая «ничего не менять до выяснения»).
4. Для записей с неизвестным исходом — `write_operation_status` (MCP) или антидубликат-поиск (прямой OData) до любых новых записей.
