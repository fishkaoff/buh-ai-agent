# onec-sales-invoices — счета на оплату покупателю

## Когда использовать

- «Выстави счёт», «счёт на…», «добавь позицию в счёт», «проведи счёт», «проверь счёт».

Документ: `Document_СчетНаОплатуПокупателю` (+ `..._Товары`). Общие правила — Skill `onec-document-management`; участники — Skills `onec-counterparties`, `onec-contracts`, `onec-nomenclature`; валидация — Skill `onec-validation`.

## Состав счёта (проверенные реквизиты)

Шапка: `Организация_Key`, `Контрагент_Key`, `ДоговорКонтрагента_Key`, `ВалютаДокумента_Key`, `СтруктурнаяЕдиница_Key` (банковский счёт организации — печатается как «реквизиты для оплаты»), `СуммаВключаетНДС`, `ДокументБезНДС`, `СуммаДокумента`, `ВидОперации` (`ТоварыИУслуги` — по умолчанию; второе допустимое — `ОсновныеСредства`), `Склад_Key` (необязателен), `Комментарий`.

Строка `_Товары` (вмещает товары и услуги): `LineNumber`, `Номенклатура` + `Номенклатура_Type` (составная ссылка!), `Содержание`, `Количество`, `Цена`, `Сумма`, `СтавкаНДС`, `СуммаНДС`, `ПроцентСкидки`, `СуммаСкидки`.

## Создание счёта

POST `Document_СчетНаОплатуПокупателю?$format=json` — проверенный payload:

```json
{
  "Date": "2026-11-10T00:00:00",
  "Организация_Key": "…", "Контрагент_Key": "…", "ДоговорКонтрагента_Key": "…",
  "ВалютаДокумента_Key": "<руб. Code 643>",
  "СтруктурнаяЕдиница_Key": "<GUID из Catalog_БанковскиеСчета>",
  "СуммаВключаетНДС": true,
  "СуммаДокумента": 100000,
  "Товары": [{
    "LineNumber": 1,
    "Номенклатура": "<GUID>", "Номенклатура_Type": "StandardODATA.Catalog_Номенклатура",
    "Содержание": "Текст, который печатается в счёте",
    "Количество": 8, "Цена": 12500, "Сумма": 100000,
    "ПроцентСкидки": 0, "СуммаСкидки": 0,
    "СтавкаНДС": "НДС20", "СуммаНДС": 16666.67
  }]
}
```

Ответ 201 → `Ref_Key` и присвоенный номер (`0000-0000NN`; `Number` не отправлять).

Порядок участников:

1. Организация — единственная/основная базы (`Catalog_Организации`), если пользователь не назвал иную.
2. Контрагент — Skill `onec-counterparties` (нет — создать с согласия).
3. Договор — Skill `onec-contracts` (вид `СПокупателем`). Счёт можно создать без договора, но для корректных расчётов договор нужен — предложите создать.
4. Банковский счёт (`СтруктурнаяЕдиница_Key`) — основной счёт организации из `Catalog_БанковскиеСчета` (см. Skill `onec-reference-data`); без него в печатной форме не будет реквизитов оплаты.

## Позиции, суммы, НДС

- `Сумма` строки = Количество × Цена (до копеек); `СуммаДокумента` = Σ строк.
- **`СуммаНДС` рассчитывайте сами** (1С через OData не пересчитывает): при `СуммаВключаетНДС=true` → `Сумма × ставка/(100+ставка)`; пример: 100000 × 20/120 = 16666,67.
- `Содержание` — текст печатной формы; для услуг обязательно.
- **Ставка НДС** — Skill `onec-validation` (по умолчанию из `config/onec-config.json`, сейчас `НДС5` — но проверена допустимость по `$metadata` этой конфигурации; явная ставка пользователя главнее; недопустимую ставку не подменять молча).
- Счёт «без НДС»: `ДокументБезНДС: true` + в строках `СтавкаНДС: "БезНДС"`, `СуммаНДС: 0`.

## Проверка после создания

1. GET шапки — сверить контрагента, договор, сумму, банк.
2. GET `..._Товары?$filter=Ref_Key eq guid'<Ref>'` — сверить строки.
3. Антидубликат: перед созданием и при повторах — поиск счетов этого контрагента за период (`Document_СчетНаОплатуПокупателю?$filter=Контрагент_Key eq guid'...' and Date ge datetime'YYYY-MM-DDT00:00:00'`) с равной суммой.

## Изменение и проведение

- Строки: PATCH с массивом `Товары` (заменяет весь набор); шапка: PATCH по ключу. Документ должен быть непроведённым.
- Проведение: PATCH `{ "Posted": true }` — **только с явного разрешения пользователя**; счёт в БП 3.0 может оставаться непроведённым (учётных движений не делает).
- Отмена проведения — PATCH `{ "Posted": false }`.

## Оплата и состояние счёта

- Оплаты по счёту — регистр накопления `AccumulationRegister_ОплатаСчетов` (движения платежей со ссылкой на счёт).
- Реализация по счёту — поиск `Document_РеализацияТоваровУслуг` с `СчетНаОплатуПокупателю_Key eq guid'<Ref>'` (Skill `onec-sales-realizations`).
- Поиск счёта по номеру: `Number eq '0000-000004'` (нумерация годовая — уточняйте период).
