# onec-nomenclature — номенклатура 1С

## Когда использовать

- Подобрать позицию для документа (счёт, реализация, поступление).
- Проверить, есть ли позиция в справочнике.
- Создать новую номенклатуру (товар или услуга).
- Узнать/установить реквизиты: вид, единица, ставка НДС, номенклатурная группа.

Метаданные `Catalog_Номенклатура` — Skill `onec-metadata` / `docs/onec-metadata-map.md`; служебные справочники — Skill `onec-reference-data`.

## Поиск и проверка наличия

```js
const items = rows((await c.req("GET", c.BASE + "Catalog_Номенклатура?$format=json&$top=1000")).body);
const found = items.filter(x => !x.IsFolder && !x.DeletionMark
  && x.Description && x.Description.toLowerCase().includes(q.toLowerCase()));
```

- Точное совпадение — равенство наименований без регистра или совпадение `Артикул`. Несколько похожих — покажите пользователю список (наименование, услуга/товар), не выбирайте молча.
- Номенклатура иерархична (`Parent_Key` — группа); в документах — только элементы (`IsFolder=false`).
- Пользователь назвал позицию своими словами («труба», «ПНД 40») — ищите по подстроке; при неоднозначности уточните.

## Ключевые реквизиты (проверено)

| Реквизит | Тип | Смысл |
|---|---|---|
| `Description` | String | наименование (обязательно) |
| `НаименованиеПолное` | String | полное наименование для печати |
| `Артикул` | String | артикул |
| `Услуга` | Boolean | `true` — услуга, `false` — товар |
| `ВидНоменклатуры_Key` | Guid | ссылка на `Catalog_ВидыНоменклатуры` |
| `ЕдиницаИзмерения_Key` | Guid | ссылка на `Catalog_КлассификаторЕдиницИзмерения` |
| `НоменклатурнаяГруппа_Key` | Guid | субконто счёта 90.01 |
| `ВидСтавкиНДС` | String | вид ставки НДС (переч. `ВидыСтавокНДС`) |

**Автозаполнение при POST (проверено на этой конфигурации)**: 1С сама подставляет вид номенклатуры (по флагу `Услуга`), единицу «шт», номенклатурную группу и `ВидСтавкиНДС: "Общая"`. Всё равно перечитывайте после создания.

Уровни ставки НДС: строка документа (основная, `СтавкаНДС`), номенклатура (`ВидСтавкиНДС` — вид), шапка документа (`ДокументБезНДС`). Правила выбора — Skill `onec-validation`.

## Создание

POST `Catalog_Номенклатура?$format=json` — минимум: `{ "Description": "Труба ПНД 40", "Услуга": false }` (или `true` для услуги), при желании сразу `НаименованиеПолное`, `Артикул`. Ответ 201 → `Ref_Key`, `Code`. Затем перечитать и при необходимости дозаполнить PATCH-ом (`ЕдиницаИзмерения_Key`, `НоменклатурнаяГруппа_Key`).

Правила:

- Тип — по поручению пользователя: «услуга» → `"Услуга": true`, «товар» → `false`; иначе уточните.
- Наименование — как назвал пользователь; без самостоятельных переименований.
- Перед созданием — поиск (антидубликат); перед повторным созданием — повторный поиск. Существующая позиция главнее новой.

## Изменение

- PATCH `Catalog_Номенклатура(guid'...')?$format=json` — только явно указанные пользователем поля; после записи перечитать.
- Не переименовывайте и не меняйте ставку НДС существующей позиции без явного поручения — на неё ссылаются проведённые документы.

## Ограничения

- Конкретная ставка НДС (`НДС5`, `НДС20`) задаётся в строках документов, не в карточке; в карточке — вид ставки (`Общая`, `Пониженная`, …). Записывать в `ВидСтавкиНДС` значения вне перечисления нельзя.
- Единицы измерения и виды номенклатуры не создавайте сами — выбирайте из существующих.
