# onec-sales-realizations — реализация товаров и услуг

## Когда использовать

- «Оформи реализацию по счёту», «отгрузка товаров», «акт на услуги», «закрывающие документы».

В этой конфигурации (Бухгалтерия предприятия 3.0) реализация оформляется документом **`Document_РеализацияТоваровУслуг`**. УПД — печатная форма этого документа; детали — Skill `onec-upd`.

## Выбор вида документа

| Что продаём | Табличная часть | Вид операции (`ВидОперации`) |
|---|---|---|
| Товары | `Товары` | `Товары` |
| Услуги (акт) | `Услуги` | `Услуги` |
| Прочие (комиссия, отгрузка без перехода права собственности, …) | — | см. перечисление `ВидыОперацийРеализацияТоваров` в `docs/onec-metadata-map.md` |

## Связь со счётом и участниками

- `Контрагент_Key`, `ДоговорКонтрагента_Key` (вид `СПокупателем`), `Организация_Key` — как в счёте.
- **`СчетНаОплатуПокупателю_Key`** — ссылка на счёт-основание, хранится **в шапке и в каждой строке**. Заполняйте обе, если реализация по счёту: это связывает документы (видно отгрузку по счёту).
- Реализация не создаётся «на основании» автоматически — все связи проставляются явным заполнением реквизитов.

## Табличные части (проверенные поля)

- `Товары`: `Номенклатура_Key`, `ЕдиницаИзмерения_Key`, `Количество`, `Цена`, `Сумма`, `СтавкаНДС`, `СуммаНДС`, `СчетУчета_Key` (41), `СчетДоходов_Key` (90.01), `СчетРасходов_Key` (90.02), `СчетУчетаНДСПоРеализации_Key` (90.03), `СчетНаОплатуПокупателю_Key`, `Содержание`.
- `Услуги`: `Номенклатура_Key`, `Содержание`, `Количество`, `Цена`, `Сумма`, `СтавкаНДС`, `СуммаНДС`, `СчетДоходов_Key`, `СчетРасходов_Key`, `СчетУчетаНДСПоРеализации_Key`, `СчетНаОплатуПокупателю_Key`.

Счета учёта: стандартные — 62.01 (расчёты, шапка `СчетУчетаРасчетовСКонтрагентом_Key`), 90.01.1 (доходы), 90.02.1 (расходы), 90.03 (НДС). **Ref_Key счетов берите ТОЛЬКО из плана счетов** `ChartOfAccounts_Хозрасчетный` фильтром по коду (`$filter=Code eq '62.01'` → `Ref_Key`): OData **не валидирует** GUID счетов при записи — угаданный GUID примется (201), но испортит документ (проверено: под «62.01» записался 83.09 и ошибка обнаружилась только перечитыванием). Иные счета — только по явному требованию (например 90.01.2/90.02.2).

## Создание

POST `Document_РеализацияТоваровУслуг?$format=json` — проверенный payload (услуги):

```json
{
  "Date": "2026-11-10T00:00:00",
  "Posted": false,
  "ВидОперации": "Услуги",
  "Организация_Key": "…", "Контрагент_Key": "…", "ДоговорКонтрагента_Key": "…",
  "СчетУчетаРасчетовСКонтрагентом_Key": "<Ref_Key счёта 62.01>",
  "БанковскийСчетОрганизации_Key": "<GUID банковского счёта>",
  "СуммаВключаетНДС": true,
  "СуммаДокумента": 100000,
  "СчетНаОплатуПокупателю_Key": "<GUID счёта-основания>",
  "Услуги": [{
    "LineNumber": 1,
    "Номенклатура_Key": "<GUID услуги-номенклатуры>",
    "Содержание": "Текст, который печатается в акте и УПД",
    "Количество": 8, "Цена": 12500, "Сумма": 100000,
    "СтавкаНДС": "НДС20", "СуммаНДС": 16666.67,
    "СчетДоходов_Key": "<90.01.1>", "СчетРасходов_Key": "<90.02.1>",
    "СчетУчетаНДСПоРеализации_Key": "<90.03>",
    "СчетНаОплатуПокупателю_Key": "<GUID счёта-основания>"
  }]
}
```

Для товаров — то же с `"ВидОперации": "Товары"`, `Склад_Key` и массивом `Товары` (`СчетУчета_Key` — 41; ссылка `Номенклатура_Key`, не составная).

Правила НДС — Skill `onec-validation`: **`СуммаНДС` строк рассчитывайте сами** — пустой `СуммаНДС` → при проведении не будет проводки Дт 90.03 Кт 68.02 (проверено). Ставка — допустимая по `$metadata`; явная ставка пользователя главнее.

## Проведение и проверка

1. Проведение — отдельной операцией, с явного разрешения: PATCH `{ "Posted": true }`.
2. Ожидаемые проводки (проверено): Дт 62.01 Кт 90.01.1 (выручка), Дт 90.03 Кт 68.02 (НДС, при заполненном `СуммаНДС`), для товаров Дт 90.02 Кт 41 (себестоимость). Читать: `AccountingRegister_Хозрасчетный` с фильтром по регистратору.
3. Товары: до проведения проверить остатки (регистры/остатки 41) — иначе красное сальдо.
4. Проверка связи: `СчетНаОплатуПокупателю_Key` в шапке и строках, суммы совпадают со счётом.

## Счёт-фактура (смежный документ)

Выданный счёт-фактура — отдельный документ на основании реализации (Skill `onec-upd`).

## Ограничения

- Услуги не требуют склада и остатков; товары — требуют.
- Проведённую реализацию не редактировать (цикл unpost → правка → post, с разрешения).
- Возвраты от покупателя — `Document_ВозвратТоваровОтПокупателя` (те же принципы).
