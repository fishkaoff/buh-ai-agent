# onec-upd — УПД и счёта-фактуры

## Когда использовать

- «Сформируй УПД», «нужен УПД по счёту/реализации», «выстави счёт-фактуру».

## Как устроен УПД в этой конфигурации (проверено)

Конфигурация — Бухгалтерия предприятия 3.0. УПД — **не отдельный документ**:

- УПД — печатная форма документа **«Реализация товаров и услуг»** (`Document_РеализацияТоваровУслуг`). Флаг `ЭтоУниверсальныйДокумент` выбирает печатную форму УПД вместо ТОРГ-12; графы счёта-фактуры печатаются из данных реализации.
- Данные печатной формы: организация, контрагент, договор, строки (`Содержание` — графа «Наименование»), суммы и ставки НДС, банковский счёт (`БанковскийСчетОрганизации_Key`), руководитель/главный бухгалтер.
- Отдельной сущности «УПД» в 1С нет (проверено по `$metadata`) — искать её не нужно.

Следствие: **сформировать УПД = правильно создать и заполнить реализацию** (Skill `onec-sales-realizations`). PDF через OData получить нельзя — Skill `onec-print-forms`.

## Счёт-фактура выданный — отдельный документ

Для книги продаж создаётся документ **`Document_СчетФактураВыданный`**. Проверено: записывайте **минимальный payload** — 1С сама наследует реквизиты (организацию, контрагента, договор, суммы, НДС) из документа-основания. Полный payload с явными `Организация_Key`/`Контрагент_Key`/суммами вызывает 500 `Не удалось записать: "Счет-фактура выданный"!` (конфликт с автозаполнением при записи).

```json
POST {BASE}Document_СчетФактураВыданный?$format=json
{
  "Date": "2026-11-10T00:00:00",
  "Posted": false,
  "ВидСчетаФактуры": "НаРеализацию",
  "ДокументОснование": "<GUID реализации>",
  "ДокументОснование_Type": "StandardODATA.Document_РеализацияТоваровУслуг",
  "ДокументыОснования": [{
    "LineNumber": 1,
    "ДокументОснование": "<GUID реализации>",
    "ДокументОснование_Type": "StandardODATA.Document_РеализацияТоваровУслуг"
  }]
}
```

Ответ 201: присвоенный номер (`0000-0000001`) и наследованные реквизиты — перечитайте СФ и сверьте `Организация_Key`, `Контрагент_Key`, `СуммаДокумента`, `СуммаНДСДокумента` с реализацией (проверено: суммы и НДС наследуются верно).

Ключевые реквизиты: `ВидСчетаФактуры` (переч. `ВидСчетаФактурыВыставленного`: `НаРеализацию`, `НаАванс`, `Корректировочный`, `НалоговыйАгент` и др.), `КодВидаОперации` («01» — реализация), `СчетФактураБезНДС`, `Выставлен`, `ДатаВыставления`.

Если POST вернул 500 — не ретраить вслепую: проверить, не создался ли СФ (поиск по виду и периоду), подождать 120 с, один повтор; при повторении — эскалация (Skill `onec-error-handling`).

## Особенности ставок НДС

- Ставка в СФ наследуется из строк реализации (`СтавкаНДС`); допустимые значения — перечисление конфигурации (Skill `onec-validation`): НДС5/7/22 в этой конфигурации отсутствуют.
- Реализация «без НДС» (`ДокументБезНДС`) — счёт-фактура не обязателен; создание СФ «без НДС» — вручную в 1С.

## Последовательность «счёт → реализация → УПД»

1. Счёт на оплату (Skill `onec-sales-invoices`).
2. Реализация по счёту со ссылкой на него в шапке и строках (Skill `onec-sales-realizations`).
3. Проведение реализации (с разрешения), проверка проводок.
4. Счёт-фактура выданный (`НаРеализацию`) — POST по минимальному шаблону выше; проверка создания обязательна.
5. Проведение СФ (с разрешения) — попадает в книгу продаж.
6. Проверка связей: `ДокументОснование` СФ = реализация; `СчетНаОплатуПокупателю_Key` реализации = счёт; суммы совпадают.
7. Печатная форма УПД/PDF — Skill `onec-print-forms` (ограничение инфраструктуры).
