# onec-document-management — документы 1С

## Когда использовать

- Создание любого документа 1С (шапка + табличная часть).
- Проведение/отмена проведения, проверка проводок.
- Изменение строк существующего непроведённого документа.

Предметные Skills поверх этого: `onec-sales-invoices` (счёт покупателю), `onec-sales-realizations` (реализация), `onec-upd` (счёт-фактура/УПД). Прочие виды документов (банк, касса, склад) создаются по тем же правилам — имена EntitySet и полей смотреть в `docs/onec-metadata-map.md`.

## Жизненный цикл документа

1. **Поиск участников** — контрагент, договор, организация, номенклатура (Skills `onec-counterparties`, `onec-contracts`, `onec-nomenclature`).
2. **Антидубликат** (Skill `onec-validation`).
3. **Создание НЕПРОВЕДЁННОГО документа** (черновик).
4. **Проверка создания** — перечитать шапку и строки.
5. **Проведение** — отдельная операция, только с явного разрешения пользователя.
6. **Проверка результата** — проводки.

## Создание: шапка + табличная часть одним POST

```json
POST {BASE}Document_<Имя>?$format=json
{
  "Date": "2026-11-10T00:00:00",
  "Организация_Key": "<GUID организации>",
  "Контрагент_Key": "<GUID контрагента>",
  "ДоговорКонтрагента_Key": "<GUID договора>",
  "ВалютаДокумента_Key": "<GUID валюты>",
  "СуммаВключаетНДС": true,
  "СуммаДокумента": 100000,
  "Товары": [
    { "LineNumber": 1, "Номенклатура": "<GUID>", "Номенклатура_Type": "StandardODATA.Catalog_Номенклатура",
      "Содержание": "Текст для печатной формы", "Количество": 8, "Цена": 12500, "Сумма": 100000,
      "СтавкаНДС": "НДС20", "СуммаНДС": 16666.67 }
  ]
}
```

Правила заполнения (проверено):

- **Даты** — `"YYYY-MM-DDT00:00:00"`, без `Z` (Skill `onec-odata`).
- **`Number` не отправляйте** — 1С присваивает сама (годовая нумерация, префикс `0000-`); ответ 201 содержит присвоенный номер.
- **Ссылки** — `_Key`; в табличных частях разных документов по-разному: у счёта — составная пара (`Номенклатура` + `Номенклатура_Type`), у реализации — `Номенклатура_Key`. Сверяйте по метаданным (Skill `onec-metadata`).
- **Содержание** строки — текст печатной формы; 1С сама не заполняет. Для услуг — обязательно.
- **Суммы**: `Сумма` строки = Количество × Цена (до копеек); `СуммаДокумента` = Σ строк; **`СуммаНДС` строки рассчитывайте сами** (1С через OData не пересчитывает): при `СуммаВключаетНДС=true` → `Сумма × ставка/(100+ставка)`, иначе `× ставка/100`. Пустой `СуммаНДС` в реализации → не будет проводки Дт 90.03 Кт 68.02.
- **Ставка НДС** — правила выбора: Skill `onec-validation` (допустимые значения — только из `$metadata`).
- Незаполненные «умные» поля (склад, счета учёта) — 1С часто подставляет при проведении; не заполняйте наугад.

## Изменение существующего документа

- Документ должен быть **непроведённым** (иначе — сначала отмена проведения, с разрешения).
- Шапка: PATCH `Document_<Имя>(guid'...')?$format=json` с изменяемыми полями.
- Строки: PATCH с массивом `Товары`/`Услуги` **заменяет табличную часть целиком** — передавайте полный набор строк со всеми реквизитами (содержание, счета учёта).
- Копия существующего документа для повторяющихся операций: прочитать документ целиком, изменить `Date` (и что требуется), POST как новый (без `Number`) — получится непроведённая копия с новым номером.

## Проведение

- PATCH `Document_<Имя>(guid'...')?$format=json`, тело `{ "Posted": true }` → 200/204.
- Отмена — `{ "Posted": false }`.
- Повторное проведение уже проведённого — не выполняйте без необходимости (получите двойные движения).

## Проверка результата

1. Перечитать шапку: `Posted`, `СуммаДокумента`, ссылки.
2. Перечитать строки: `..._Товары?$filter=Ref_Key eq guid'<Ref документа>'` — количества, цены, ставки, НДС.
3. Проводки проведённого: GET `AccountingRegister_Хозрасчетный?$filter=Recorder eq guid'<Ref>'`-запрос или Skill-инструменты аналитики; ожидаемую схему проводок см. в предметных Skills.
4. Ошибки проведения — Skill `onec-error-handling`.

## Связи документов

- Реализация ← счёт: реквизит `СчетНаОплатуПокупателю_Key` в шапке **и в строках** реализации (Skill `onec-sales-realizations`).
- Счёт-фактура ← реализация: составная ссылка `ДокументОснование` + таблица `ДокументыОснования` (Skill `onec-upd`).
- Оплата ← счёт: регистр накопления `AccumulationRegister_ОплатаСчетов` (движения платежей со ссылкой на счёт).

## Ограничения

- Создание и проведение — всегда разные операции.
- Проведённый документ не редактируется (цикл: unpost → правка → post — проверен).
- Не удаляйте и не помечайте документы на удаление без явного разрешения.
