# onec-print-forms — печатные формы и PDF

## Когда использовать

- «Дай PDF счёта», «распечатай», «отправь клиенту документ».

Tools: `export_document_pdf` (официальный PDF по запросу); PDF также
прикладываются к ответу автоматически при создании счёта.

## Как работает (важно)

- PDF формирует **сама 1С** (HTTP-сервис печати в расширении) — это
  официальные печатные формы, можно отправлять клиенту. Черновиком НЕ являются.
- PDF **не сохраняются**: файл прикладывается к ответу (`files` в ответе
  API, base64) и существует только в рамках этого ответа.
- В контекст LLM файлы не попадают — из результата Tools видны только
  метаданные (имя, размер). Не пытайтесь «прочитать» PDF из Tool-результата.

## Автоматически при создании счёта

`create_sales_invoice` после создания документов сам забирает PDF счёта и
PDF УПД — они прикладываются к ответу (в результате Tools это видно как
`invoice_pdf` и `upd_pdf` с именем и размером). Черновики печатных форм
(`invoice_draft`, `upd_draft`) появляются в результате только если
официальные PDF не получены (сервис печати не настроен или ошибка —
см. `pdf_errors`).

## По запросу — export_document_pdf

1. `export_document_pdf(document_type, ref_key, database)`:
   - `document_type="invoice"` — счёт на оплату (Ref_Key счёта);
   - `document_type="realization"` — УПД (Ref_Key **реализации**:
     печатная форма УПД формируется из документа «Реализация товаров и услуг»).
2. Файл прикладывается к ответу автоматически (`attached_to_reply=true`).
3. Ошибка «сервис печати не настроен» — предложите черновик из результата
   `create_sales_invoice` или печать из 1С вручную; развёртывание сервиса
   на стороне 1С — `docs/onec-print-http-service.md`.
4. Ошибка от сервиса (HTTP 4xx/5xx) — передайте пользователю суть ошибки;
   ошибки формирования печатной формы — задача на сторону 1С (эскалация,
   не повторять вызовы).

## Черновики печатных форм

- Черновик строится из данных документа и помечен «ЧЕРНОВИК — не заменяет
  печатную форму 1С». Показывайте как предпросмотр, не выдавайте за
  официальный документ.
- Проверка корректности: номер, дата, реквизиты (ИНН/КПП), каждая строка
  (содержание, количество, цена), итоги, ставка и сумма НДС — с документом
  1С (Skill `onec-validation`). Расхождение — файл не отдавать.

## Ограничения

- Стандартный OData печатные формы не отдаёт — не пытайтесь «печатать»
  POST-ами к произвольным URL 1С.
- Для PDF УПД в расширении должен быть шаблон `realization` — без него
  счёт-PDF будет получен, а УПД останется черновиком (ошибка — в `pdf_errors`).
