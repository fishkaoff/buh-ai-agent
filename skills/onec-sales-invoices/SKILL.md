# onec-sales-invoices — счета на оплату покупателю

## Когда использовать

- «Выстави счёт», «счёт на…», «добавь позицию в счёт», «покажи счёт».

Tools: `create_sales_invoice`, `update_sales_invoice_lines`, `get_document`,
`list_allowed_vat_rates`; вспомогательные — Skills `onec-counterparties`,
`onec-contracts`, `onec-nomenclature`, `onec-validation`.

## Создание счёта (полный сценарий)

`create_sales_invoice` за один вызов создаёт **связку документов**: счёт на
оплату → реализация товаров и услуг → счёт-фактура (УПД), а также возвращает
черновики печатных форм. Отдельно реализацию и УПД создавать не нужно.

Порядок:

1. Контрагент: `find_counterparty` (Skill `onec-counterparties`).
2. Договор: `find_contract`, при отсутствии — предложите создать
   (Skill `onec-contracts`).
3. Позиции: наименования, количества, цены; для каждой — услуга или товар
   (Skill `onec-nomenclature`). Номенклатура ищется/создаётся внутри Tool.
4. Ставка НДС: явная ставка пользователя главнее; иначе дефолт из настроек
   приложения (Skill `onec-validation`).
5. Оберните сценарий в операцию: `create_operation` → `create_sales_invoice`
   → `complete_operation` со списком созданных документов.

Аргументы `lines` — список позиций: `name` (обязательно), `price` (обязательно),
`quantity` (по умолчанию 1), `is_service`.

## Антидубликат

Если у контрагента уже есть непроведённые счёта за сегодня, Tool вернёт ошибку
со списком номеров и **не создаст дубликат**:

- это тот же заказ → доработайте существующий счёт (`update_sales_invoice_lines`);
- пользователь подтверждает отдельный новый счёт → повторите вызов с
  `force_new=true` (только после явного подтверждения).

## Доработка существующего счёта

`update_sales_invoice_lines` заменяет строки счёта и синхронно обновляет связанную
реализацию. Требования:

- `lines` — **ПОЛНЫЙ** список позиций (существующие + новые), не только новые;
- счёт и реализация должны быть непроведёнными (Tool проверит и откажет);
- работает только в рамках активной операции — не создавайте новый счёт вместо
  доработки, если счёт уже создан в этой операции.

Счёт-фактура (УПД) обновления не требует: её сумма вычисляется при проведении.

## Чтение документа

`get_document` (`document_type`: `invoice` — счёт, `realization` — реализация)
возвращает человекочитаемую сводку: участники, суммы, строки, статус проведения.

## Правила

- Проведение документов через Tools не выполняется — проведение в 1С делает
  бухгалтер; операция после `complete_operation` уходит пользователю на подтверждение.
- Ref_Key и номера документов — только из результатов Tools.
- Если данных не хватает (нет позиций, цен, контрагента) — уточняющий вопрос.
