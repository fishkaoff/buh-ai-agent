# onec-validation — валидация данных 1С

## Когда использовать

- Перед созданием любого документа — до вызова создающего Tool, а не после.
- При сомнениях в данных пользователя (ставка НДС, суммы, несколько похожих объектов).

Tools: `list_allowed_vat_rates`; правила также применяют сами Tools приложения.

## Ставка НДС

1. **Пользователь явно назвал ставку → использовать её.** Не подменять дефолтом.
2. Иначе — дефолт из настроек приложения (`ONEC_VAT_RATE`).
3. Допустимость ставки проверяется по `$metadata` 1С (Tool делает это сам и
   вернёт ошибку со списком допустимых). Факт по этой конфигурации: допустимы
   `БезНДС, НДС0, НДС10, НДС10_110, НДС18, НДС18_118, НДС20, НДС20_120`;
   **ставок НДС5/НДС7/НДС22 нет** — запись отклоняется.
4. Ставки нет в конфигурации → сообщите пользователю и спросите, чем заменить
   (например `НДС20` или `БезНДС`). Молча не подменяйте.
5. Уточнить допустимые ставки заранее можно Tool-ом `list_allowed_vat_rates`.

## Суммы и НДС

- Сумма строки = Количество × Цена (до копеек); сумма документа = Σ строк.
- По умолчанию суммы «в том числе НДС» (`includes_vat=true`): НДС строки =
  Сумма × ставка / (100 + ставка). Пример: 100 000 × 20/120 = 16 666,67.
- «Без НДС»: ставка `БезНДС`, сумма НДС = 0.
- Количество > 0, цена ≥ 0 в каждой позиции; для услуг понятно, что оказывается
  (наименование/содержание — текст печатной формы).

## Контроль дублей

- Контрагент, номенклатура, договор — перед созданием поиск; найдено → использовать.
- Счета: непроведённые счёта контрагента за сегодня блокируют создание
  (см. Skill `onec-sales-invoices`).
- Повторный вызов после ошибки — сначала повторный поиск, потом запись:
  OData 1С идемпотентности не имеет.

## Ссылки

- Все `ref_key` — только из результатов Tools в этой же базе. Не придумывайте
  и не берите идентификаторы из памяти или других баз: несуществующий GUID
  даёт пустой результат, а не ошибку.
- Договор принадлежит контрагенту документа; банковский счёт — организации.
