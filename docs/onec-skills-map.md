# Карта Skills для работы с 1С

Дата: 10.11.2026. Все Skills **самодостаточны и не зависят от MCP**: они описывают операции в терминах прямых OData-запросов к 1С (Skill `onec-odata` + `config/onec-config.json` + `config/onec/odata-client.js`). Это позволяет использовать их в OpenCode, LangGraph или любом другом runtime без переписывания. MCP-сервер `1c-odata` (если он установлен в среде) — необязательный ускоритель; его инструменты перечислены в `docs/onec-capabilities.md`.

## 1. Состав библиотеки

### Транспорт и метаданные (фундамент)

| Skill | Назначение | Ключевые скрипты/refs |
|---|---|---|
| `onec-odata` | Транспорт: URL, фильтры (`substringof`/`eq`), пагинация, POST/PATCH, типы данных, безопасная запись (payload → согласие → запись → сверка) | `config/onec/odata-client.js` |
| `onec-metadata` | Исследование метаданных: `$metadata` XML, поиск EntitySet, поля/типы, перечисления | `scripts/metadata_extract.js` |
| `onec-error-handling` | Формат `odata.error`, HTTP-коды, неизвестный исход записи, ошибки проведения, эскалация | `references/errors.md` |
| `onec-validation` | Чек-листы до записи/до проведения: ссылки, дубли, суммы, ставки НДС (по `$metadata`), счета учёта из плана счетов | — |

### Справочники и участники

| Skill | Назначение | Зависится от |
|---|---|---|
| `onec-reference-data` | Поиск/создание/изменение элементов справочников; служебные справочники (валюты, единицы, виды, склады, банки) | onec-odata, onec-metadata |
| `onec-counterparties` | Контрагенты: поиск по ИНН/наименованию, дубли, карточка, создание/изменение, группы | onec-odata, onec-reference-data, onec-validation |
| `onec-contracts` | Договоры: поиск по владельцу и виду, выбор последнего, правила нумерации, создание | onec-reference-data, onec-validation |
| `onec-nomenclature` | Номенклатура: поиск, реквизиты, автозаполнение 1С, создание товара/услуги без дублей | onec-reference-data, onec-validation |

### Документы

| Skill | Назначение | Зависится от |
|---|---|---|
| `onec-document-management` | Общие правила документов: шапка+табличная часть POST-ом, проведение, правка строк, проверка | onec-odata, onec-validation, onec-error-handling |
| `onec-sales-invoices` | Счёт покупателю: полный payload, банк (`СтруктурнаяЕдиница`), суммы/НДС, проведение, оплата | onec-document-management + контрагенты/договоры/номенклатура |
| `onec-sales-realizations` | Реализация (`Document_РеализацияТоваровУслуг`): товары/услуги, связь со счётом (шапка+строки), счета учёта, проводки | onec-document-management, onec-upd |
| `onec-upd` | УПД (печатная форма реализации) и счёт-фактура выданный (минимальный payload, наследование) | onec-sales-realizations, onec-error-handling |
| `onec-print-forms` | Печатные формы и PDF: подтверждённые ограничения и альтернативы | — |

## 2. Используемые источники данных

- Прямой OData: `config/onec-config.json` (базы, креды, значения по умолчанию — НДС/валюта/организация), клиент `config/onec/odata-client.js` (`client()`, `req()`, `rows()`, `parseError()`, `docDate()`).
- `$metadata` (XML) — единственный источник перечислений и полей; разбор — `scripts/metadata_extract.js` из Skill `onec-metadata`.
- Никакого другого состояния Skills не хранят (без бизнес-состояния внутри Skills).

## 3. Типовые последовательности

### Выставить счёт покупателю (базовый поток)

```
onec-counterparties: найти контрагента (ИНН/наименование) → нет? создать (с согласия)
onec-contracts:      найти договор СПокупателем → нет? создать (нумерация по правилам skill)
onec-nomenclature:   найти позиции → нет? создать (товар/услуга)
onec-validation:     ставки НДС по $metadata; суммы; дубли счетов
onec-sales-invoices: POST счёта → перечитать шапку+строки
```

### «Счёт → реализация → УПД» (закрытие продажи)

```
onec-sales-invoices:      счёт (см. выше)
onec-sales-realizations:  POST реализации со СчетНаОплатуПокупателю_Key (шапка+строки),
                          счета учёта — из плана счетов по коду
                          → провести (с разрешения) → проверить проводки
onec-upd:                 POST счёта-фактуры минимальным payload → проверить наследование → провести
onec-print-forms:         PDF недоступен — человек печатает из 1С (или черновик-предпросмотр)
```

### Разовая услуга новому клиенту (сценарий A)

Поток «Выставить счёт» + договор «на работы» (`СПокупателем`) + номенклатура-услуга (`"Услуга": true`, заполнить `Содержание` строки) + реализация-акт (табличная часть `Услуги`) + УПД по необходимости.

### Поставка товаров по текущему договору (сценарий B)

Поток «Выставить счёт» + существующий договор + номенклатура-товар + реализация-отгрузка (`ВидОперации: "Товары"`, склад, остатки!) + УПД по необходимости.

## 4. Правила безопасности (сквозные)

- Любая запись: предпросмотр payload → явное согласие → POST/PATCH → перечитывание-сверка.
- Проведение — отдельная операция, только с разрешения пользователя.
- Дубли исключаются поиском перед каждым созданием и перед повторными вызовами.
- Не удалять, не менять существующее без разрешения; тестовые данные — только в тестовой базе и с пометкой в наименовании.
- Значения перечислений и счетов учёта — только проверенные из `$metadata`/плана счетов (не «по памяти»).

## 5. Известные пробелы (требуют доработки вне Skills)

1. Печатные формы/PDF — нужна доработка 1С (HTTP-сервис); детали — Skill `onec-print-forms`.
2. Ставки НДС 5%/7%/22% — конфигурация 1С не обновлена (перечисление их не содержит).
3. Счёт-фактура при полном payload — 500 (обход: минимальный payload, проверено).
4. MCP-поиска номенклатуры нет (только контрагенты) — в Skills используется прямой OData.
5. Регистр «Счета учёта расчётов с контрагентами» не опубликован в OData.
